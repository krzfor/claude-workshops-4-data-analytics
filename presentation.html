Why it's better

Not just a number — a system.

The old dashboards gave you a result. The engine gives you a result you can defend.

🏷️
Every result is versioned
Each response includes definition_version: v1.0. Historical results stay tagged to the rules that produced them. No silent recalculations.
🧪
Testable, not trusted
31 automated tests covering calculation logic and the HTTP layer. Edge cases are in the test suite, not in someone's head.
💬
Explainable per customer
The /churn/explain endpoint says in plain English exactly why a customer is (or isn't) counted. No more "the dashboard just shows it."
📐
Definition is a first-class document
Every edge case lives in definition.md with rationale. Changing logic means bumping the version — code and doc can't drift apart.
The engine — live API

Ask the engine anything. Get a versioned answer.

Three endpoints. Every response carries the definition that produced it.

# What is our churn this quarter? GET /churn?period=2024-Q1 { "logo_churn_pct": "7.23%", "revenue_churn_pct": "5.90%", "active_at_start": 332, "churned_count": 24, "definition_version": "v1.0" }
